# Debuff System (디버프)

플레이어에게 걸리는 시한 상태이상을 한곳에 모은 문서다. 현재는 식중독·출혈·물에 젖음 세 가지이며, 이후 추가되는 디버프도 여기에 정리한다. 수치는 `data-src/debuffs.csv`에서 관리하고, 정의 로드는 `server/src/debuff_defs.rs`, 서버 로직은 `server/src/game_state/debuff.rs`, 와이어 타입은 `shared/src/debuff.rs`에 있다. 배고픔 자체는 [HUNGER.md](HUNGER.md), HP 회복 규칙은 [COMBAT.md](COMBAT.md)를 참고한다.

## 공통 규칙

- 디버프는 종류별로 하나만 유지한다. 같은 디버프에 다시 걸리면 중첩하지 않고 지속시간을 처음부터 다시 센다.
- 서로 다른 디버프는 동시에 걸릴 수 있으며, 배수는 곱해서 적용한다. 예를 들어 쇠약(×0.75)과 식중독(×0.6)이 겹치면 이동 속도는 0.45다.
- 시간이 지나거나 사망·리스폰하면 사라진다. 접속 종료 시에도 사라지며 DB에 저장하지 않는다.
- 걸림·해제는 전투 로그와 HUD의 디버프 아이콘, 캐릭터 상태 창의 효과 카드로 알린다. 남은 시간은 해당 플레이어에게만 보낸다.
- 확률 판정과 지속·틱 처리는 모두 서버가 한다.
- 공식 NPC와 에이전트 플레이어에는 배고픔과 같은 면제 플래그를 적용한다.

## debuffs.csv

| 열 | 뜻 |
|----|----|
| `id` | 디버프 식별자. 다른 CSV에서 이 값으로 참조한다. |
| `name` | 표시 이름 |
| `chance` | 발동 조건이 성립했을 때 걸릴 확률(%) |
| `durationSecs` | 지속시간(초) |
| `dps` | 1초마다 입는 피해. 비어 있으면 피해 없음 |
| `moveMult` / `attackMult` / `carryMult` | 이동 속도·공격 속도·최대 하중 배수. 비어 있으면 1 |
| `drainMult` | 포만도 활동 소비 배수. 비어 있으면 1 |
| `blocksRegen` | true면 HP 자연 회복이 멈춘다 |

현재 값:

| id | name | chance | durationSecs | dps | moveMult | attackMult | carryMult | drainMult | blocksRegen |
|----|------|--------|------------|-----|----------|------------|-----------|-----------|-------------|
| food_poisoning | Food Poisoning | 70 | 300 | | 0.6 | 0.6 | 0.6 | 4 | true |
| bleed | Bleeding | 35 | 8 | 1 | | | | | true |
| wet | Wet | 100 | 450 | | 0.83 | | | | |

아이콘과 문구는 클라이언트의 `debuffPresentation.ts`에 둔다. CSV에는 게임 수치만 적는다 (쉼표 금지, `data/debuffs.json`은 생성물).

확률은 디버프별로 하나만 둔다. 같은 디버프를 여러 출처가 서로 다른 확률로 걸어야 하는 상황이 오면 출처 쪽 CSV에 덮어쓰기 열을 추가한다.

## 출처 연결

- **몬스터 공격**: `monsters.csv`의 `hitDebuff` 열에 디버프 id를 적으면 명중할 때마다 해당 확률로 건다. 놀은 `hitDebuff=bleed`.
- **음식**: `items.csv`의 `useDebuff` 열. 날생선 5종은 `useDebuff=food_poisoning`.
- **물 진입**: 이동 처리가 직접 건다 (`server/src/game_state/debuff.rs`의 `soak_movers`). CSV 참조가 아니라 코드에 id가 박혀 있다.

## 식중독 (food_poisoning)

날생선을 먹으면 70% 확률로 5분간 걸린다. 이동 속도·공격 속도·최대 하중 ×0.6, 포만도 활동 소비 4배, HP 자연 회복 정지. HP에 직접 피해는 없다. 구운 생선은 걸리지 않는다. 자세한 배경은 [HUNGER.md](HUNGER.md)의 "날생선과 식중독" 절을 참고한다.

## 출혈 (bleed)

발톱·이빨류 몬스터의 명중 시 35% 확률로 8초간 걸린다. 1초마다 1의 피해를 입어 총 8의 피해이며, 지속 중에는 HP 자연 회복이 멈춘다. 다시 맞아 또 걸리면 지속시간만 8초로 갱신된다.

- 출혈 피해로 사망할 수 있다. 처치자는 없으며 일반 사망과 같이 처리한다.
- 출혈 틱은 `last_combat_at`을 갱신하지 않고 음식 HP 회복(`FoodRegeneration`)도 취소하지 않는다. 출혈 중 음식을 먹어 버티는 것은 의도된 대응이다.
- 붕대처럼 출혈을 즉시 멈추는 아이템은 아직 없다. 추가한다면 `items.csv`에 `curesDebuff` 열을 두는 방식을 검토한다.

## 물에 젖음 (wet)

강이나 바다에 발을 들이면 걸린다. 이동 속도 ×0.83으로, 뛰기가 4.5에서 3.75(걷기 3.0과 뛰기 4.5의 중간)로 떨어지고 걷기는 2.5가 된다. 지속시간 450초는 게임내 1시간이다 (게임 하루 = 현실 3시간, `time.rs::REAL_DAY_DURATION_SECONDS`). 다른 페널티는 없다.

- 판정은 이동 틱(200 ms) 뒤 `soak_movers`가 한다. 걸음이 끝난 지점의 수심(수면 − 지형)이 0.4 m를 넘으면 젖는다. 얕은 강가는 젖지 않는다.
- 물속을 계속 걸으면 지속시간이 갱신된다. 물에서 나오면 그때부터 450초 뒤에 마른다.
- 지형 샘플링은 이동 락을 놓은 뒤에 하고, 이미 젖은 사람은 남은 시간이 300초 밑으로 떨어지기 전까지 건너뛴다. 움직이는 사람도 1초에 한 번만 검사한다 (플레이어 id로 5틱에 나눠 담는다).
- 샘플링은 16개씩 동시에 돈다(`WATER_CHECK_CONCURRENCY`). 캐시에 있는 타일은 마이크로초라 차이가 없지만, 캐시가 빈 상태(재배포 직후 재접속 몰림)에서 타일 파일을 하나씩 순서대로 읽으면 이동 틱이 그만큼 밀린다. [fishing.rs](../server/src/game_state/fishing.rs)가 첫 타일 IO를 틱 밖으로 빼둔 것과 같은 이유다.
- 물속에 가만히 서 있기만 하면 갱신이 없어 450초 뒤 마른다. 갱신이 이동에 붙어 있기 때문이며, 의도한 동작이다.
- 지상(floor 0)에서만 검사한다. 집 2층·던전에는 물이 없다.

### 모닥불에 말리기

불 켜진 모닥불 3 m 안(`CAMPFIRE_GRILL_RADIUS`, 굽기와 같은 거리)에 있으면 1초에 10초씩 마른다 — 꽉 젖은 상태에서 45초면 다 마른다. 배율은 `debuff.rs`의 `CAMPFIRE_DRY_SECS_PER_SEC`다.

- 1초 배고픔 스윕에서 `tick_campfire_drying`이 `tick_debuffs` 직전에 돌며 만료 시각만 앞당긴다. 실제 해제와 알림은 평소처럼 `tick_debuffs`가 한다.
- 앉을 필요는 없다. 반경 안에 있기만 하면 마른다.
- 모닥불의 층(floor)이 같아야 한다.
- 누가 피웠는지는 상관없다. NPC가 `/light_campfire`로 피운 불도 똑같이 말린다. 밤에 피운 불은 해 뜰 때까지 타므로 오히려 더 오래 쓸 수 있다.
- 젖은 사람이 없거나 켜진 모닥불이 없으면 읽기 락 두 번으로 빠져나온다. 둘 다 있을 때만 거리 검사를 돈다.
- 남은 시간이 줄어드는 속도가 달라지므로 말리는 동안 매초 `DebuffUpdate`를 다시 보낸다. 대상은 불 옆에 있는 사람뿐이다.

### 젖은 발자국

젖어 있는 동안 뒤로 발자국이 남는다 (`client/src/lib/effects/wet-footprints.ts`, `GameSceneFootprintsLayer.svelte`). 순수 클라이언트 연출이라 서버는 그리는 데 관여하지 않는다.

- 0.75 m 걸을 때마다 좌우 번갈아 한 개. 15초 동안 진하게 남았다가 다음 15초에 걸쳐 마른다 (`PRINT_LIFETIME_S` 30초, 앞 `PRINT_HOLD` 절반은 최대 진하기).
- 인스턴스 1,024개 풀을 화면 위 모든 사람이 나눠 쓰므로 드로우콜은 1회다. 뛰면 초당 6개씩 찍히니 전력 질주하는 사람 두어 명분이 들어가고, 넘치면 링 버퍼가 가장 오래된 것부터 지운다. 발자국은 한 번 찍히면 움직이지 않으므로 행렬은 찍을 때 한 번만 쓰고 매 프레임 갱신하는 건 불투명도뿐이다.
- **곱하기 블렌딩**이다. 조명 없는 고정 색을 일반 알파로 얹으면 밤에 지면이 어두워지면서 발자국만 허옇게 뜬다. 지면 색에 곱하면 조명을 저절로 따라간다. 진하기는 `wet-footprints.ts`의 `WET_TINT` (낮을수록 진하다).
  - **WebGPU에서는 `premultipliedAlpha = true`가 필수다.** 없으면 three가 블렌딩을 거부하고 경고만 남긴 뒤 그냥 불투명하게 그린다 — 화면에는 흰 네모로 나온다. 노드 파이프라인은 알파를 미리 곱해주지 않으므로 `colorNode`에 `WET_TINT × mask`를 직접 실어야 하고, 그러면 블렌딩 결과가 `dst × mix(1, tint, mask)`가 되어 발바닥 밖은 지면이 그대로 남는다.
- **물 위에는 안 찍는다.** 발이 수면보다 아래면(`waterSurfaceAt`, 클라의 베이크된 수면) 건너뛴다 — 강바닥에 찍혀 물 밑으로 비쳐 보이던 것을 막는다. 물에서 나오는 순간부터 자국이 시작된다.
- 발자국은 걷는 사람의 발 높이(`position.y`)에 찍으므로 집 2층·던전 바닥에서도 맞는다.
- 한 프레임에 5 m 넘게 움직이면(텔레포트·리스폰·세계 x 이음매) 자국을 남기지 않고 누적 거리를 버린다.

**본인**: `DebuffUpdate`로 남은 시간을 알기 때문에 마를수록 자국이 옅어진다. `until`을 찍는 순간 확인하므로 서버 스윕 사이에 만료돼도 바로 멈춘다. 그래픽 설정과 무관하게 항상 그린다.

**다른 플레이어**: 방송되는 `Player.wet` 플래그로 그린다. 남은 시간은 와이어에 싣지 않으므로 자국 진하기는 고정이다. **그래픽 품질 `high`에서만 그린다** (`enableRemoteFootprints`; 모바일 프리셋은 강제로 끈다). 서버는 보는 쪽 설정을 알 수 없으니 플래그는 항상 보내며, 설정을 high로 바꾸면 즉시 보인다.

`Player.wet`은 `inflict_debuff` 안에서 뒤집는다 — 젖음을 거는 경로가 나중에 늘어나도(비, 아이템, GM 명령) 플래그가 호출자마다 따라붙을 필요가 없게 한 곳에 뒀다. 해제는 `tick_debuffs`의 `retain`이 유일한 경로이므로, 나중에 `curesDebuff` 같은 즉시 해제를 넣는다면 목록에서 빼지 말고 `until`을 현재로 당겨서 스윕이 처리하게 해야 한다.

방송은 `set_player_wet`이 비교 후 바뀔 때만 한다(`PlayerTorchToggled`와 같은 모양). 물속을 걸으며 매 걸음 갱신되는 것은 와이어에 나가지 않고, 플래그는 젖을 때와 마를 때 한 번씩만 뒤집힌다 — 5,000명이 전부 젖었다 말랐다 해도 초당 20여 건이다. 사망(`clear_debuffs`)도 플래그를 내린다.

와이어가 바뀌므로 `PROTOCOL_VERSION`을 39 → 40으로 올렸다. 배포하면 구버전 탭은 접속이 거절되고 업데이트 안내를 받는다.

## 규모 측정

`wet_path_cost_at_scale` (무시 표시된 측정용 테스트, `cargo test wet_path_cost_at_scale -- --ignored --nocapture`). 5,000명 기준 디버그 빌드 수치:

| 항목 | 시간 |
|------|------|
| `water_depth_at` 캐시 적중 | 2.8 us/회 |
| `soak_movers`, 5,000명 전원 이동·아무도 안 젖음 (1틱) | 3.5 ms |
| `soak_movers`, 5,000명 전원 이동·전원 이미 젖음 (1틱) | 0.20 ms |
| `tick_campfire_drying`, 젖은 사람 없음 | 0.14 ms |
| `tick_campfire_drying`, 5,000명 젖음 × 모닥불 200개 | 5.1 ms |

`soak_movers`는 200 ms마다 도니 최악의 경우 초당 17.5 ms — 릴리스 빌드면 그보다 훨씬 적다. 젖음 갱신 게이트가 실제로 먹는지도 위 표의 2·3행 차이로 확인된다.

다른 플레이어 발자국은 따로 재지 않았다. 비용이 접속자 수가 아니라 AOI 안에 보이는 인원(수십 명)에 묶여 있고, 프레임마다 그 인원만큼 거리 계산 한 번씩이다.

측정에 안 잡힌 건 타일 최초 로딩(디스크 IO)이다. 캐시에 없는 타일은 파일 두 개(8.5 KB + 17 KB)를 읽고, `soak_movers`는 후보를 순차로 await한다. 정상 운영 중에는 사람이 서 있는 타일을 초당 5번 건드리므로 300초 TTL에 걸려 밀려나지 않아 문제가 안 되지만, 서버 재시작 직후처럼 전부 차가운 상황에서는 이동 틱 한두 번이 늘어질 수 있다. 문제가 되면 틱당 후보 수에 상한을 두는 것이 가장 싼 대응이다.

## 후보

- 독(poison): 출혈과 같은 dps형. 지속이 길고 dps가 낮은 구성으로 거미·뱀류에 사용.
- 화상(burn): 짧고 dps가 높은 구성.
- 둔화(slow): `moveMult`만 쓰는 구성. 얼음·거미줄류 (물에 젖음과 같은 형태).
- 기절(stun): 행동 불가는 지금 열로 표현할 수 없어 새 열이 필요하다.
