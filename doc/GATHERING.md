# Gathering System: Woodcutting (채집·벌목)

> 상태: 설계안, 미구현 (2026-08-03)

필드의 자원 노드를 직접 채집하는 공통 흐름과 첫 활동인 벌목을 정의한다.
플레이어는 벌목용 도끼를 장착하고 필드의 나무를 클릭해 장작을 얻으며,
가방에서 부싯돌을 사용해 장작을 모닥불로 바꾼다. 모닥불의 지속 시간과
생선 굽기는 기존 [HUNGER.md](HUNGER.md) 구현을 그대로 사용한다. 벌목이
귀찮거나 주변 나무가 고갈된 플레이어는 상점의 비싼 Campfire Kit로 이 과정을
건너뛸 수 있다.

## 목표

- 필드 풍경이 채집 대상이 되어 탐험과 아이템 생산이 연결된다.
- 클릭 한 번으로 이동, 벌목 동작, 나무 쓰러짐, 보상까지 자연스럽게 이어진다.
- 자원 판정과 보상은 서버 권위로 처리해 중복 획득과 클라이언트 조작을 막는다.
- 기존 TR01 나무 배치, 지상 아이템 드롭·줍기, 모닥불 AOI 시스템을 재사용한다.
- 직접 채집하는 저비용 경로와 돈으로 시간을 사는 편의 경로를 함께 유지한다.
- 이후 광석, 약초 같은 자원을 추가할 수 있는 흐름을 만들되 첫 구현부터 범용
  프레임워크를 과도하게 만들지는 않는다.

## 범위 밖

첫 구현에는 도구 내구도, 도끼 등급, 희귀 부산물, 제작법, 벌목 스킬 레벨,
파티 공동 채집, 쓰러진 나무의 충돌을 넣지 않는다. `Skills`에는 현재 Fishing만
있으며, 벌목 숙련은 보상과 도구 티어를 설계할 때 별도 단계로 추가한다.

## 플레이 흐름

```text
벌목용 도끼 장착
      │
      ▼
필드 나무 클릭 ── 멀면 접근 ──► 3회 도끼질
      │                              │ 이동·피격·사망·장비 교체
      │                              └──────────────► 취소
      ▼
나무 쓰러짐 ──► 장작 2개 바닥 드롭 ──► 직접 줍기 ──► 부싯돌 사용
                                                        │ 장작 1개 소비
                                                        ▼
                                                  모닥불 10분 생성
```

1. 일반 상인 Rica에게 `Lumber Axe`와 `Flint and Steel`을 산다. Lumber Axe는
   전리품에서 월드 드랍으로 얻을 수도 있다.
2. `Lumber Axe`를 주 손에 장착한 채 지상의 나무를 클릭한다.
3. 멀리 있는 나무라면 플레이어가 나무 앞까지 자동으로 이동한다. 도착하면
   나무를 향해 선 뒤 약 3초 동안 세 번 도끼질한다.
4. 마지막 타격이 서버에서 확정되면 나무가 플레이어 반대편으로 쓰러진다.
   나무가 바닥에 닿을 때 `Firewood` 2개가 밑동 주변에 떨어지며 플레이어가
   직접 클릭해 줍는다.
5. 가방에서 `Flint and Steel`을 더블 클릭하면 장작 1개를 소비하고 바라보는
   방향 1m 앞에 모닥불을 피운다. 부싯돌은 사라지지 않는다.
6. 벌목을 원하지 않으면 Rica에게 비싼 `Campfire Kit`을 사서 바로 사용한다.
   도끼, 부싯돌, 장작 없이 같은 모닥불 하나를 만든다.

현재 인벤토리에는 아이템을 다른 아이템 위에 사용하는 조작이 없다. 따라서
“장작에 부싯돌 사용”은 **부싯돌 사용 → 가방에서 장작 1개 자동 선택**으로
해석한다. 장작이 없으면 아무것도 소비하지 않고 필요한 재료를 안내한다.

## 초기 튜닝

| 항목 | 값 | 비고 |
|---|---:|---|
| 벌목 상호작용 거리 | 나무 중심에서 2.5m | 클라이언트 접근 목표는 약 1.8m |
| 벌목 시간 | 3.0초 | 1초 간격 3타, 마지막 타격이 드롭을 확정 |
| 동시 작업자 | 나무당 1명 | 선점 후 다른 플레이어는 `사용 중` 응답 |
| 장작 획득량 | 나무당 2개 | 나무 종류·크기와 무관한 첫 튜닝 |
| 나무 재생성 | 게임 시간 7일 후 | 현실 약 21시간, 서버 재시작 시 모두 복구 |
| 장작 소모 | 모닥불당 1개 | 부싯돌은 재사용 |
| 모닥불 지속 | 10분 | 기존 `CAMPFIRE_DURATION_MS` 유지 |
| Campfire Kit 가격 | 50c | 기존 30c에서 인상하는 편의 비용 |

수치는 구현 상수가 되며 플레이 테스트 후 조정한다. 게임 하루는 현실 3시간이므로
게임 7일은 서버가 실행되는 현실 시간 약 21시간이다. 한 나무는 모닥불 20분
분량을 제공하지만 빈자리는 다음 날까지 남아, 많이 이용한 숲이 눈에 띄게
고갈되고 다른 숲을 찾거나 Campfire Kit을 사는 선택이 생긴다. 이 21시간 규칙은
한 서버 프로세스가 계속 실행되는 동안에만 적용된다. 첫 구현의 고갈 상태는 메모리
전용이라 서버가 재시작되면 경과 시간과 관계없이 모든 나무가 즉시 복구된다.

## 아이템과 경제

| id | 이름 | 형태 | 초기 가격 | 역할 |
|---|---|---|---:|---|
| `lumber_axe` | Lumber Axe | 주 손, 비스택 | 2s | 벌목 도구, `1d4` 근접 피해 |
| `flint_and_steel` | Flint and Steel | 사용 가능, 비스택 | 20c | 장작을 모닥불로 점화, 사용해도 유지 |
| `firewood` | Firewood | 스택 가능 | 5c | 모닥불 하나를 만들 때 1개 소비 |
| `campfire_kit` | Campfire Kit | 스택 가능 | 50c | 재료·도구 없이 모닥불 하나를 즉시 설치 |

- 벌목용 도끼는 `category: "weapon"`, `dice: "1d4"`,
  `gatheringTool: "woodcutting"`으로 둔다. 전투에서는 힘 보정과 무기 강화 수치를
  적용하는 정상 근접 무기지만, 피해는 단검·횃불과 같은 최저 무기군이다. 맨손
  `1d2`보다는 낫고 낡은 검·창의 `1d6`, 철검의 `1d8`보다 약하다. 무기 강화는
  전투 피해에만 영향을 주며 벌목 시간이나 장작 획득량은 바꾸지 않는다.
- 도끼는 Rica가 상시 판매하며 `data-src/world_drop.csv`에도 1% 독립 롤로 넣는다.
  현재 월드 드랍의 공통 규칙대로 몬스터 처치, 던전 상자, 파괴 가능한 오브젝트 등
  전리품이 발생하는 모든 지점에서 정상 보상에 더해 나올 수 있다. 상점 판매품인
  실용 도구이므로 희귀 거래템이 아니라 가끔 도구 구입비를 아껴 주는 보너스다.
- 도끼에는 `chestTier`를 지정하지 않는다. 따라서 던전의 정규 장비 풀이나
  시그니처 보상에는 포함되지 않으며, 던전 상자에서 보이더라도 1% 월드 드랍이
  별도로 적중한 결과다. 부싯돌은 상점 전용 시작 도구로 유지한다.
- 장작은 판매할 수 있지만 나무 한 그루의 판매가는 10c에 불과하다. 벌목은
  초기에 돈벌이보다 모닥불 자급 수단이며, 경제 역할은 숙련 시스템을 넣을 때
  다시 평가한다.
- `campfire_kit`은 Rica의 상시 판매 목록에 남긴다. 가격은 30c에서 50c로 올린다.
  장작 한 개의 기준가 5c보다 10배 비싸지만 도끼·부싯돌 구입, 나무까지 이동,
  3초 벌목, 주변 나무의 게임 시간 1주일 재생 대기를 모두 생략하는 값이다.
  한두 번 쓸 때는 키트가 간편하고, 반복해서 모닥불을 쓰는 플레이어는 도구를 산
  뒤 직접 벌목하는 편이 빠르게 저렴해진다.
- 키트와 `firewood`는 같은 장작 묶음 모델과 아이콘을 사용할 수 있다. 이름을
  구별할 필요가 생기면 키트 아이콘에 끈이나 부싯깃을 더한다. 실제 파일을
  이동하거나 새 자산을 추가할 때는
  [assets/items.md](assets/items.md)의 항목도 함께 갱신한다.

## 어떤 나무를 벨 수 있는가

- 대상은 `/api/terrain/trees/{x}/{z}`가 제공하는 TR01 배치의 `tree1`, `tree2`
  인스턴스다. 화면에만 임의 생성된 복제물이 아니라 서버도 같은 원본 바이트를
  읽고 확인할 수 있다.
- 지상(`floor_level == 0`)의 활성 나무만 가능하다. 던전과 집의 위층에서는
  시작할 수 없다.
- 마을 경관과 시작 지점을 보호하기 위해 `NoSpawnZone` 내부 나무는 장식물로
  취급하고 벌목할 수 없다. 주택 배치 시 TR01에서 제거된 나무도 당연히 대상이
  아니다.
- 고갈은 TR01 파일에서 인스턴스를 삭제하지 않는다. 주택이 나무를 영구 제거하는
  작업과 플레이어가 일시적으로 자원을 채집하는 작업은 서로 다른 상태다.

### 안정적인 나무 식별자

기존 코드에서 `tile_x`, `tile_z`는 나무 한 그루가 아니라 64×64m 지형 타일
하나를 가리킨다. 한 타일에는 여러 나무가 있으므로 그 값을 그대로 쓰면 부족하다.
다만 현재 배치기는 타일 안의 64×64 셀을 순회하며 **셀당 최대 한 그루**만
생성하므로, 타일과 로컬 셀을 합친 전역 셀 좌표 두 개면 충분하다.

```rust
struct TreeId {
    grid_x: i32,
    grid_z: i32,
}
```

`grid_x = tile_x * 64 + cell_x`, `grid_z = tile_z * 64 + cell_z`다. 서버는 Euclidean
division으로 타일과 로컬 셀을 다시 얻고 해당 TR01 레코드를 찾는다. 나무 종류,
정확한 위치, 회전, 스케일은 ID에 반복해서 싣지 않고 레코드에서 복원한다. 베이크
단계는 전역 셀 하나에 두 레코드가 생기지 않는다는 계약을 검증한다. 배열 순번과
달리 주택 건설로 다른 나무가 삭제되어도 ID가 바뀌지 않는다.

## 서버 상태와 권위

서버에는 두 개의 작은 런타임 맵을 둔다.

- `chop_sessions: PlayerId -> ChopSession`: 대상 나무, 시작 위치, 완료 시각.
- `depleted_trees: TreeId -> respawns_at_game_seconds`: 이미 쓰러져 다시 자라는
  중인 나무의 월드 시계 만료 시각.

`GameState`에는 `TerrainIO`를 직접 노출하기보다 이를 사용하는 `TreeCatalog`를
주입한다. 카탈로그는 TR01 파싱과 지연 타일 캐시, `TreeId` 조회를 책임진다.
주택 건설·수정이 TR01 파일을 바꾸면 현재의 `TreeTilesInvalidated` 흐름에서 서버
캐시도 같은 타일을 제거하고 그 타일을 대상으로 한 벌목 세션을 취소한다. 제거된
나무가 오래된 캐시에 남아 벌목되는 창을 허용하지 않는다.

요청 시 서버는 다음을 모두 다시 검증한다.

1. 플레이어와 나무가 존재하고 둘 다 지상에 있는가.
2. 나무가 보호 구역 밖이고 아직 고갈되지 않았는가.
3. 다른 세션이 같은 나무를 선점하지 않았는가.
4. 주 손 아이템의 `gatheringTool`이 실제 `woodcutting`인가.
5. 현재 XZ 거리가 허용 범위 안이며 지형 높이가 일치하는가.
6. 플레이어가 살아 있고 다른 집중 행동을 수행 중이지 않은가.

시작 시 나무를 선점한다. 완료 틱은 세션 제거와 고갈 등록을 한 임계 구역에서
처리해 두 플레이어가 같은 나무의 드롭을 만들 수 없게 한다. `TreeFelled` 후
1초짜리 낙하 연출이 끝나면 서버가 서로 다른 instance id를 가진 `firewood`
지상 아이템 두 개를 밑동 주변 0.6m 안에 흩뿌린다. 위치는 기존
`loot_drop_position`으로 통행 가능한 지면에 보정한다.

장작은 가방에 자동으로 들어가지 않는다. 현재 지상 아이템 규칙을 그대로 따라
누구나 주울 수 있고 30분 뒤 사라진다. 가방 공간이나 하중이 부족하면 줍기만
거절되고 장작은 남아 있다. 첫 구현에는 별도 소유권을 추가하지 않으며, 가로채기가
문제가 되면 벌목자에게 몇 초간 우선 획득권을 주는 방안을 검토한다.

이동, 피격, 사망, 접속 종료, 주 손 장비 변경은 벌목을 취소하고 선점을 해제한다.
벌목 시작은 낚시와 굽기를 먼저 취소하며, 반대로 다른 집중 행동의 시작도 벌목을
취소한다. 취소 전에는 장작을 드롭하거나 나무를 고갈시키지 않는다. 마지막 타격이
확정된 뒤에는 플레이어가 이동하거나 접속을 종료해도 쓰러짐과 장작 드롭이 끝까지
진행된다.

고갈 상태는 첫 구현에서 메모리에만 유지한다. 벌목 완료 시 현재
`current_total_game_seconds()`에 게임 7일을 더해 런타임 맵에 기록하고, 만료
틱은 항목을 제거한 뒤 `TreeRespawned`를 방송한다. 서버가 재시작되면 맵은 비워진
상태로 시작해 모든 나무가 복구된다.

고갈 영속화는 후속 작업이다. 운영 중 재시작을 이용한 반복 벌목이 경제 문제가
되거나 산림 상태를 재시작 너머까지 보존할 필요가 확인되면
`tree_depletions(grid_x, grid_z, respawns_at_game_seconds)` 테이블을 추가한다.
그때도 현실 UNIX 시각이 아니라 저장된 월드 시각을 사용해 서버가 꺼진 동안에는
나무가 자라지 않는 규칙을 유지한다.

## 네트워크

다음 메시지 모양을 기준으로 다음 프로토콜 버전에서 구체화한다.

### 클라이언트 → 서버

- `ChopTree { tree_id }`: 접근을 마친 뒤 벌목을 시작한다.
- `StopGathering`: 명시적으로 현재 벌목을 취소한다.
- `RequestTreeStates { tiles }`: 막 로드한 TR01 타일의 고갈 상태를 요청한다.

클라이언트가 멀리서 나무를 클릭했을 때 보내는 이동 경로는 기존 이동 프로토콜을
사용한다. 도착 후에만 `ChopTree`를 보낸다. `RequestTreeStates`는 한 요청의 타일
수와 플레이어 주변 범위를 제한해 임의의 월드 스캔 수단이 되지 않게 한다.

### 서버 → 클라이언트

- `TreeChopStarted { player_id, tree_id, rotation, finishes_in_ms }`: 주변 플레이어가
  벌목 자세와 도끼질 타이밍을 재생한다.
- `TreeChopCancelled { player_id, tree_id }`: 캐릭터를 기본 자세로 돌린다.
- `TreeFelled { tree_id, fall_rotation, respawns_in_ms, revision }`: 인스턴스를
  쓰러지는 단일 모델로 전환하고 이후 숨긴다.
- `TreeRespawned { tree_id, revision }`: 나무 인스턴스를 다시 표시한다.
- `TreeStates { tile, depleted, revision }`: 타일 스트리밍·재접속 시 놓친 상태를
  보정한다.
- `GatheringError { reason }`: 도구 없음, 거리 초과, 보호 구역, 사용 중, 고갈 등
  본인에게만 보이는 거절 사유다.

시작·취소·쓰러짐·재생성은 기존 이벤트 전달 반경 안에만 방송한다. 정적 나무
목록을 WebSocket 스냅샷에 싣지 않고 기존 HTTP 타일을 유지하며, `TreeStates`는
고갈된 소수 ID만 전달한다. 서버는 타일마다 상태 `revision`을 두고 고갈·재생성
때 증가시킨다. 클라이언트는 자신이 적용한 revision보다 오래된 응답이나 이벤트를
버려, HTTP 타일 로드 중 실시간 이벤트와 상태 응답 순서가 뒤집히는 경합을 막는다.

## 클라이언트 입력과 표현

### 클릭과 접근

`GameSceneTreeLayer`의 `InstancedMesh` raycast 결과에는 `instanceId`가 들어온다.
레이어가 렌더 슬롯과 `TreeId`의 매핑을 제공하고, 입력 처리기는 도끼가 주 손에
있을 때 나무 클릭을 `chop_tree` 의도로 우선 해석한다. 도끼가 없을 때 나무는
기존처럼 이동 클릭을 방해하지 않는다.

현재 `TreePlacementData`는 디코딩 뒤 부동소수점 렌더 버퍼만 보존한다. TR01을
읽을 때 타일 좌표와 원본 로컬 좌표가 속한 셀로 `TreeId` 배열을 만들고 인스턴스
순서와 나란히 보관해, raycast의 `instanceId`를 프로토콜 ID로 바꾼다.

나무가 상호작용 거리 밖이면 나무 중심에서 약 1.8m 떨어진 접근점을 계산해
이동하고, 도착 시 다시 대상의 존재와 장비를 확인한 뒤 시작 메시지를 보낸다.
이동 중 대상이 다른 플레이어에게 쓰러지면 의도를 취소한다.

### 캐릭터와 나무 애니메이션

- 캐릭터: 첫 구현은 기존 공격 클립 `slash1`을 벌목 시작 후 0초, 1초, 2초에
  한 번씩 총 3회 재생한다. 이는 연출만 재사용하며 일반 공격 메시지, 피해 판정,
  주변 몬스터 어그로를 발생시키지 않는다. 서버 시작 이벤트의 `finishes_in_ms`에
  맞춰 원격 캐릭터도 같은 박자로 보이고, 취소 이벤트를 받으면 반복을 즉시 멈춘다.
  전용 벌목 애니메이션은 동작 품질을 높이는 후속 교체 항목으로 남긴다.
- 도끼: 주 손 소켓과 기존 무기 장착 렌더 경로를 그대로 쓴다.
- 나무: `TreeFelled`를 받으면 해당 인스턴스를 전역 인스턴스 목록에서 제외하고,
  같은 GLB를 독립 모델로 잠시 승격한다. 줄기 밑동을 피벗으로 1.0초 동안
  `fall_rotation` 방향으로 회전시킨다.
- 쓰러진 모델은 4초 뒤 사라지고 재생성까지 빈자리로 남는다. 첫 구현에는 별도
  그루터기 모델과 충돌을 두지 않는다.
- 낙하 방향은 벌목 완료 순간의 나무→플레이어 벡터 반대편을 서버가 계산해
  방송한다. 모든 클라이언트가 같은 방향을 보며, 지형·플레이어 충돌 판정에는
  영향을 주지 않는 연출이다.

필요 자산은 벌목 도끼 모델·아이콘, 부싯돌 아이콘, 도끼 타격음, 나무 쓰러지는
소리다. 생성·구매 전에는 기존 자산을 임의로 출처 표기하지 않으며,
실제 추가 시 `doc/assets/`의 해당 파일에 라이선스와 생성일을 기록한다.

## 모닥불 점화의 두 경로

직접 채집 경로와 편의 구매 경로는 결과가 완전히 같다. 어느 쪽으로 피워도 기존
`Campfire` 엔티티 하나가 생기며 지속 시간, 설치 제한, AOI, 공유 요리 규칙에
차이가 없다. 키트에 더 오래 타는 효과를 주지 않는다. 편의성 자체가 구매 가치다.

### 장작과 부싯돌

`flint_and_steel`의 `UseEffect::LightFire`는 다음 순서로 처리한다.

1. 가방에 `firewood`가 1개 이상 있는지 확인한다.
2. 기존 모닥불 키트와 같은 위치 계산을 한다: 바라보는 방향 1m 앞, 막혔으면
   발밑 후보.
3. 실외, 지상, 비수중, 통행 가능 위치인지 검증한다.
4. 검증이 모두 끝난 뒤에만 장작 1개를 차감한다.
5. 기존 `spawn_campfire`를 호출하고 “모닥불을 피웠다” 메시지를 보낸다.

부싯돌은 `consumable` UI 플래그상 사용 가능한 아이템이지만 서버는 부싯돌 자체를
차감하지 않는다. 실패 시 부싯돌과 장작 모두 유지된다. 모닥불의 AOI, 10분 소멸,
3m 굽기 반경, 공유 사용 규칙은 변경하지 않는다.

### Campfire Kit

`campfire_kit`은 기존 `UseEffect::PlaceCampfire` 경로를 유지한다. 사용 시 키트
하나만 소비하며 도끼, 부싯돌, 장작 보유 여부를 묻지 않는다. 설치 위치 검증이
성공한 뒤에만 소비하고, 설치가 불가능하면 키트를 보존한다. Rica는 수량 제한 없이
50c에 판매해 마을 주변 나무가 모두 재생 대기 중이어도 모닥불을 얻을 수 있게 한다.

## 에이전트 동등성

agent-client도 TR01 타일과 고갈 상태를 읽어 사람과 같은 `TreeId`를 선택한다.
LLM 액션은 다음 두 가지를 제공한다.

```json
{"type":"chop_tree","x":123.0,"z":456.0}
{"type":"light_campfire","source":"auto"}
```

좌표를 생략한 `chop_tree`는 관측 범위의 가장 가까운 활성 나무를 고른다. 접근과
3초 타이밍은 이동·낚시처럼 반사 계층이 처리하고, 시작·완료·거절은 `[Gathering]`
이벤트로 모델에 전달한다. `source`는 `firewood`, `kit`, `auto` 중 하나이며
`auto`는 장작+부싯돌을 먼저 쓰고 재료가 없을 때만 비싼 키트를 사용한다. 서버
검증은 사람 클라이언트와 완전히 동일하다.

`chop_tree`는 나무가 쓰러지면 끝나며 장작을 자동으로 줍지 않는다. 떨어진 장작은
기존 월드 관측의 ground item으로 나타나고, 에이전트도 사람처럼 별도의 `pickup`
액션으로 하나씩 주워야 한다.

## 실패 처리

| 상황 | 결과 |
|---|---|
| 도끼 없이 시작 | `도끼를 장착해야 한다`, 상태 변화 없음 |
| 대상이 멀거나 사라짐 | 시작 거절 또는 이동 의도 취소 |
| 다른 플레이어가 작업 중 | `누군가 벌목 중이다`, 선점 유지 |
| 도끼질 중 이동·피격·장비 교체 | 세션 취소, 나무와 보상 유지 |
| 완료와 두 번째 요청이 경합 | 먼저 완료한 한 명만 장작 2개를 드롭시킴 |
| 가방/하중 초과 | 줍기 거절, 장작은 30분 제한까지 지상에 유지 |
| 장작 없이 부싯돌 사용 | 재료 안내, 아무것도 소비하지 않음 |
| 모닥불 설치 불가 | 위치 안내, 아무것도 소비하지 않음 |
| 벌목 중 서버 종료 | 보상 없음, 재시작 후 나무 활성 |
| 나무 고갈 후 서버 재시작 | 메모리 상태 초기화, 모든 나무 즉시 복구 |

## 검증 계획

### 서버 계약 테스트

- TR01 바이트에서 `TreeId`를 안정적으로 복원하고 잘못된 타일·셀은 거절한다.
- 나무 베이크 결과는 한 타일 셀에 최대 한 레코드만 갖는다.
- 거리, 지상, 보호 구역, 도끼 장착, 활성 상태 검증이 각각 독립적으로 동작한다.
- 벌목용 도끼는 전투에서 `1d4` 무기 피해를 주고, 강화 수치는 전투에만 적용된다.
- 벌목용 도끼에 `chestTier`가 없어 던전의 정규 장비 풀에서 제외된다.
- 월드 드랍 테이블에 벌목용 도끼가 정확히 1%로 등록되고 정상 아이템 정의를
  가리킨다.
- 한 나무를 동시에 요청해도 세션 하나만 시작되고 장작 두 개가 한 번만 드롭된다.
- 이동·피격·죽음·장비 변경·접속 종료가 세션과 선점을 정리한다.
- 정상 완료는 낙하 연출 뒤 장작 지상 아이템 2개를 만들고 가방은 변경하지 않는다.
- 장작을 주우면 기존 스택에 합쳐지며, 하중 초과 시 아이템이 지상에 보존된다.
- 고갈된 나무는 게임 시간 7일 전에는 거절되고 만료 틱 이후 다시 벌목할 수 있다.
- 새 서버 프로세스는 고갈 상태가 없는 빈 런타임 맵에서 시작한다.
- 부싯돌은 유지되고 장작만 1개 줄며, 설치 실패 시 둘 다 보존된다.
- Campfire Kit은 50c에 계속 판매되고, 사용 시 키트만 하나 줄어든다.
- 두 점화 경로가 동일한 10분짜리 `Campfire`를 생성한다.
- 기존 모닥불 굽기와 10분 소멸 테스트는 그대로 통과한다.

### 클라이언트 테스트

- 인스턴스 슬롯이 올바른 `TreeId`로 역매핑된다.
- 도끼 장착 여부에 따라 같은 클릭이 벌목 또는 이동으로 해석된다.
- 벌목 시작은 `slash1`을 1초 간격으로 3회 재생하고 취소 시 남은 반복을 멈춘다.
- 고갈 상태를 받은 나무만 인스턴스 렌더에서 제외된다.
- 쓰러짐 모델이 정해진 방향·시간으로 재생되고 4초 뒤 정리된다.
- 타일을 다시 로드했을 때 `TreeStates`로 고갈 상태가 복원된다.
- 늦게 도착한 낮은 revision의 상태 응답이 최신 쓰러짐·재생성 이벤트를 덮지 않는다.

## 구현 순서

1. 아이템 정의, 벌목용 도끼 1% 월드 드랍, `campfire_kit` 가격 조정·상시 판매,
   부싯돌 점화 경로.
2. 공유 `TreeId`·프로토콜과 서버 TR01 조회 캐시, 벌목 세션·메모리 재생성 틱.
3. 클라이언트 나무 raycast, 자동 접근, 고갈 필터, 쓰러짐 연출.
4. 전용 모델·아이콘·SFX와 자산 출처 문서화.
5. agent-client 액션과 관측 이벤트, 전체 계약 테스트.

각 단계는 이전 단계의 임시 우회 없이 최종 데이터 흐름을 향해 진행하되, 새
자원 종류가 실제로 추가되기 전에는 벌목 코드를 억지로 범용 trait 계층으로
추상화하지 않는다.

## 후속 아이디어: 불법 벌목과 경비병

현재 MVP는 `NoSpawnZone` 안의 마을 나무를 벌목할 수 없게 막는다. 향후 범죄·감옥
시스템이 생기면 이 제한을 단순 해제하는 대신 **불법이지만 가능한 행동**으로
바꾸는 것을 검토한다.

1. 플레이어가 마을 나무에 도끼질을 시작하면 가까운 경비병이 다가와 먼저
   벌목을 중단하라고 경고한다.
2. 경고를 받고 멈추면 처벌하지 않거나 가벼운 기록만 남긴다.
3. 계속 벌목하거나 다시 시도하면 범죄 수치가 오르고 경비병이 체포를 시도한다.
4. 체포되면 일정 시간 감옥에 수감되거나 벌금을 내고 풀려난다.
5. 몰래 벌목하거나 경비병의 시야를 피하는 플레이도 가능하게 해, 금지 안내가
   아니라 위험을 감수하는 선택으로 만든다.

장작 보상, 목격 판정, 경고 유예 시간, 지명 수배, 저항 시 전투, 감옥 탈출 등은
범죄 시스템 전체와 함께 설계한다. 이 아이디어를 구현하기 전까지는 마을 나무를
서버가 즉시 거절하는 현재 MVP 규칙을 유지한다.
