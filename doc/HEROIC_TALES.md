# Heroic Tales — 영웅담

서버에서 실제로 일어난 사건을 바드 Signe가 서사시로 부른다. 실명이 나온다.
[TITLES.md](TITLES.md)가 "내가 잡았다"의 증명을 캐릭터에 붙인다면, 영웅담은 그 증명을
**저녁 여관에서 남들이 듣게** 만든다.

## 왜

- 칭호는 본인 머리 위에만 뜬다. 다른 플레이어가 "누가 처음 오거 군주를 잡았는지"를 알
  길이 없다. 영웅담은 서버 역사를 공유 지식으로 만든다.
- 경제에 닿지 않는다. 골드·아이템 발행 없이 동기(이름이 노래에 오르고 싶다)를 준다.
- Signe는 이미 있다(`data-src/npcs.csv`, `agent-client/data/templates/bard.txt`). 지금은
  "이번에는 X를 부르겠습니다" 외에 할 말이 없다. 세계에서 실제로 벌어진 일이 그 빈자리를
  채운다.
- 불운도 노래가 된다. +9에서 부서진 검, 보스 앞에서 한 걸음 모자란 죽음은 비극으로 각색하면
  당사자에게도 위로가 되고, 듣는 사람에겐 인챈트·던전이 얼마나 위험한지를 규칙표보다 잘
  전한다([DESIGN_DIRECTION.md](DESIGN_DIRECTION.md)의 "싱크는 인챈트 도전으로").

## 파이프라인 — 사실과 노래를 분리한다

```
1. 수집   매일 prod 로그 감사 중 사건 추출            (사람 + Claude, 오프라인)
2. 기록   사실만 원장(ledger)에 한 줄씩 추가            (텍스트 파일, prod)
3. 공연   코드가 원장에서 오늘의 주제를 고르고, Signe가 과장·각색해 부른다 (agent-client)
```

사실은 사람이 적고, 노래는 바드가 만든다. 서사시는 원래 과장과 각색이 본질이라 검수할
대상이 아니다. 지켜야 할 선은 하나뿐이다 — **원장에 없는 사건과 인물을 만들지 않는다.**
"고블린 셋을 잡았다"가 "고블린 떼가 그 이름만 듣고 흩어졌다"가 되는 건 노래다. "보스 앞에서
도망쳤다"를 지어내는 건 실명에 없는 일을 붙이는 것이고, 당사자가 여관에서 듣는다.

"특별한 사건이 없으면 한 노래가 오래 간다"는 원장에 새 줄이 없으면 같은 재료를 계속 부르는
것으로 자연히 충족된다. 별도 상태가 없다.

## 1. 수집 — 사건 카탈로그

`prod-log-audit` 스킬에 단계 하나를 더한다. 감사 창(직전 배포 → 지금) 안에서 아래를
뽑는다. 로그 문구는 `server/src`에서 확인한 실제 줄이다.

| 사건 | 검출 | 원장에 적는 것 | 지금 검출 |
|---|---|---|---|
| 최고 레벨 갱신 | `Player NAME reached level N` + DB `characters` 최고 레벨과 비교 | 이름, 레벨, 이전 최고 보유자 | 가능 |
| 창 안 최다 레벨업 | `Player NAME reached level N` 을 이름별로 count | 이름, 오른 레벨 수, 도달 레벨 | 가능 |
| 창 안 최다 경험치 | 로그에 XP 줄이 없다. 감사 때 DB `characters(name, level, xp)`를 스냅샷으로 남기고 직전 스냅샷과 차이를 본다 | 이름, 순위만 (수치 없음) | 스냅샷 시작 뒤부터 |
| 마을에서 제일 멀리 간 사람 | 좌표가 찍히는 줄(`killed … at (x,z)`, `died … at (x,z)`)과 DB `characters.last_x/last_z`에서 Aldermark(`map_labels.csv`, -1475,4742)와의 거리 최대. 가장 가까운 `map_labels` 이름을 같이 적는다 | 이름, 거리 순위, 근처 지명 | 부분 — 싸우지 않고 걷기만 한 사람은 로그아웃 위치로만 잡힌다 |
| 보스 처치 | `Guardian of 'ENTRANCE' fell at depth D`와 같은 시각의 `Player NAME killed BOSS (lvl N) at … PLACE` | 이름, 보스, 던전, 홀로 여부 | 가능 |
| 칭호 획득 | `Player NAME earned title 'ID'`. 오프라인 부여는 `Character ID earned title 'ID' while offline`이라 DB로 이름을 찾는다 | 이름, 칭호 | 가능 |
| 서버 최초 보스 처치 | 위 칭호 로그 + 원장에 그 칭호가 처음 등장 | "최초" 표시 | 원장으로 가능 |
| 인챈트 고단 성공 | `NAME enchanted ITEM to +N` (창 안 최고·서버 최고) | 이름, 아이템, +N | 가능 |
| 인챈트 파괴 | `NAME destroyed ITEM enchanting at +N` (+N ≥ 7 정도) | 이름, 아이템, 부서진 단계 | 가능 |
| 보스 앞 사망 | `Player NAME died to CAUSE at … PLACE` 의 CAUSE가 보스 | 이름, 보스, 던전 | 부분 — "아슬하게"(보스 잔여 HP)는 로그에 없다 |
| 부자 | DB `characters.gold` 상위 변동, 대형 `Trade:` 이전 | 이름, 순위 변동만 (금액 없음) | 가능 |
| 트로피 물고기 | 낚시에는 `info!` 로그가 없다. 칭호(`sturgeon_angler`)로만 잡힌다 | 이름, 어종 | 칭호 있는 어종만 |
| 스트릭·누적 | 같은 이름의 연속 보스 처치, 하루 N마리 | 이름, 횟수 | 원장 누적으로 가능 |
| 어뷰즈 | 감사에서 서버 규칙을 악용해 이득을 얻은 것으로 확정된 사건(예: 층 재입장 리스폰 초기화) | 이름, 수법 id, 던전, 오른 레벨 | 사람 판정 |

최다 레벨업·최다 경험치·최원거리는 매 감사마다 한 명씩 나오는 **상시 엔트리**다. 보스·인챈트처럼
드문 사건이 없는 날에도 원장에 줄이 생기고, 저레벨 신인이 주인공이 되는 유일한 길이다.
같은 사람이 계속 1위면 매일 적지 않고 "N일째"로 스트릭 줄 하나만 적는다.

**로그 보강 후보** (필요해지면 서버에 한 줄씩 추가):
- 보스 사망 시 보스 잔여 HP 비율 — "한 방만 더 쳤으면"을 사실로 만들 유일한 근거.
- 낚시 성공 `info!` — 트로피·희귀 어종 전부를 잡기 위해.
- 지명 진입 `info!`(`map_labels` 반경에 처음 들어올 때) — "Brovik에 닿은 첫 사람"을 사실로.
  개인별 방문 기록이 서버에 없으므로 `character_dungeon_discoveries` 같은 부속 테이블이
  하나 더 필요하다. 지금은 좌표 로그로 대신한다.
- 인챈트 결과 줄에 보유 최고값 — 지금은 DB 조회로 대신한다.

## 2. 기록 — 원장

**공개 리포 밖**에 둔다. 플레이어 실명이 들어가므로 감사 노트(`~/work/notes`)와 같은 원칙이다.
선례는 `agent-client/data/npcs/*/memory.txt`·`favor.json` — gitignore된 NPC별 파일을 prod에
직접 쓴다.

```
agent-client/data/tales/ledger.txt     사실 원장. 추가만 하고 지우지 않는다
~/work/notes/openmmo-YYYY-MM-DD-xp.tsv  감사 때 뜬 (name, level, xp) 스냅샷. 다음 감사의 비교 기준
```

`npcs/signe/` 아래가 아니라 `tales/`인 이유: Rica가 같은 사건을 소문으로 말하거나 Karl이
한마디 하는 확장이 후보에 있다. 원장은 NPC 소유가 아니라 세계 소유다.

원장 한 줄 형식:

```
2026-09-02  boss_kill      용사A  ogre_boss  ogre_dungeon  solo=false  first=true
2026-09-02  enchant_break  용사B  iron_sword  +9
2026-09-01  level_record   용사C  32  prev=용사A:31
2026-09-02  most_levels    용사D  +6  reached=14
2026-09-02  most_xp        용사A  streak=3
2026-09-02  farthest       용사E  near=brovik  dist=6300
2026-09-04  exploit        용사F  respawn_reset  ogre_dungeon  from=20  to=25
```

- 날짜, 사건 종류, 이름, 사건별 필드. 공백(탭도 됨) 구분, `key=value`와 위치 인자, 자유 형식 없음. `#` 줄은 주석. 코드가 파싱해 문장으로
  풀어 Signe에게 주고, 다음 감사가 "이미 기록됐는가"와 "서버 최초인가"를 여기서 판정한다. TITLES.md가 미뤄 둔
  "서버 최초 처치의 영속 마커"를 이 원장이 겸한다.
- 이름은 **사건 당시 캐릭터명**. 개명(`renamed to` 로그)·삭제(`Character id=N deleted`)가
  보이면 감사 때 원장 줄의 이름을 고치거나 줄을 지운다(아래 규칙). 원장을 고쳐 쓰는 경우는
  이 둘뿐이다: 개명·삭제에 따른 이름 수정, 어뷰즈로 확정된 성과(최다 경험치·레벨 줄)의 제거.
- 한국어·영어를 따로 두지 않는다. 원장은 id와 이름뿐이고, 언어는 Signe가 청중에 맞춘다.

## 이름·표현 규칙

실명이 나가는 콘텐츠라 규칙이 필요하다. 공지 작성 기조(사실 위주, 수치 제외)와 같은 결이다.

- **실패는 비극이지 조롱이 아니다.** 부서진 검은 "운명이 거둬 간" 것이지 "멍청하게 날린" 것이
  아니다. 당사자가 여관에서 들었을 때 웃거나 뿌듯해야지 불쾌해선 안 된다.
- **어뷰즈는 조롱 대상이다.** 실패가 아니라 커뮤니티의 규칙을 악용해 개인 이득을 취한 것이므로
  `exploit` 줄은 `mocking` 분위기로 수법을 비웃는 노래가 된다. 수법과 허영만 비웃고, 그 밖의
  모욕·위협·처벌 선동은 없다. 어뷰즈 판정은 감사에서 원인이 확정된 뒤에만 한다.
- **봇도 똑같이** 노래에 오른다. 봇이 최초 보스 킬을 했으면 그 이름이 영웅이다. 운영 NPC
  계정(`npc_` 접두사)만 제외 — 이들은 배경이다.
- **금액·IP·계정명은 절대 쓰지 않는다.** "부자"는 "금고가 넘친다"까지. 얼마인지, 누구와
  거래했는지는 안 나간다. 대형 이전은 리롤·자산 이동인 경우가 많아 사건 자체가 노래감이
  아니다.
- **개명한 캐릭터**는 현재 이름으로 부른다. 감사 때 원장을 고친다. **삭제된 캐릭터**는
  원장에서 뺀다 — 없는 사람을 노래하면 "그런 사람 없는데?"가 된다.
- **한 이름이 연속으로 주인공이 되는 것**은 막지 않는다. 사실이 그렇다면 그렇게 부른다. 다만
  같은 사람의 같은 종류 사건(매일 보스 킬)은 원장에 첫 번과 스트릭만 적는다.
- 노래에 오르기 싫은 플레이어가 나오면 그때 제외 목록(`tales/opt_out.txt`)을 둔다. 미리
  만들지 않는다.

## 3. 공연 — Signe 연동

서버는 `/recite` 한 줄, 클라이언트는 말풍선 한 case. 나머지는 agent-client다.

- **고르는 건 코드, 부르는 건 LLM.** 원장 전체를 LLM에 주고 "알아서 골라라"고 하면
  선택·중복 관리·기억이 전부 LLM 몫이 되고 그만큼 틀린다. 대신:
  - 여관 공연 일정이 시작될 때 코드가 원장에서 **오늘의 주제 3개**를 뽑는다. 최근 줄에
    가중치를 두되 랜덤이다 — 어제 것이 오늘 또 나올 수 있고, 새 줄이 없어도 매일 다른
    조합이 된다. 같은 이름이 셋 다 차지하지 않게 이름당 하나.
  - 매 턴 프롬프트에는 **그 셋 중 하나**만 `=== TONIGHT'S TALE (a true deed — sing it as
    you like) ===` 절로 넣는다. 원장 줄을 사람이 읽는 영어 문장으로 풀어서 준다("Alder
    slew the Ogre Warlord. Nobody had ever done it before."). 청중 언어로 옮기는 건
    bard.txt대로 Signe 몫이다.
  - 어느 것을 몇 번 불렀는지는 코드가 센다. `recite`가 나간 턴마다 다음 주제로 넘기고,
    셋을 다 돌면 처음으로. LLM은 "지금 이 주제"만 안다.
  - **곡 두 개 간격.** 이야기 하나 → 그 곡 → 평소 곡 둘 → 다음 이야기. 자기 곡 시작
    횟수를 세어, 마지막 이야기 뒤 곡이 셋 지나야 절을 다시 넣는다. 사이에는 절이 없으니
    평소처럼 곡 소개를 하고 논다. 늦게 온 사람도 듣고, 세 주제가 밤새 도는 일도 없다.
  - 원장이 없거나 비어 있으면 절 자체를 넣지 않는다. Signe는 지금처럼 논다.
  - `build_system_prompt`에 굽지 않는다 — 시스템 프롬프트는 재시작(=배포) 때만
    만들어지는데 배포는 드물고 원장은 매일 자란다. 원장은 공연이 시작될 때 읽는다.
    낮에 감사가 줄을 더하면 그날 저녁부터 후보에 든다.
- **한 턴에 세 동작.** 다음 곡을 초대하는 신호가 오면 Signe는 같은 턴에 (1) 분위기를 알리는
  한 줄 `say`("오늘은 전설적인 영웅담을…" / "오늘은 슬픈 이야기를…" — 프롬프트의 `Mood:`가
  정한다. 파괴·보스 사망은 비극, 어뷰즈는 조롱, 나머지는 영웅담), (2) 다섯 절 이상의 가사를 담은 `recite`,
  (3) 곡 제목 소개 없이 `/play_music`만 낸다 — 분위기 한 줄이 소개를 대신한다.
- **가사는 첫 바퀴만 채팅창에, 반복은 말풍선에만.** `recite`의 절은 agent-client가 9초마다
  하나씩 보낸다. 첫 바퀴는 `/recite <절>`, 이후 반복은 `/recite_quiet <절>`. 서버는 둘 다
  `ServerMessage::Recital`(`logged` 플래그)로 채팅 범위에 뿌리고, 클라이언트는 말풍선을
  띄우되 `logged`일 때만 채팅 로그에 쓴다. 절은 곡이 끝날 때까지 순환하고,
  곡이 끝나거나 자리를 뜨면 멈춘다. 곡을 안 틀면 25초 뒤 멈춘다. 이 메시지 추가로
  프로토콜이 v50이 됐다. 채팅창에 남는 건 분위기 한 줄과 가사 한 바퀴뿐이다.
- **언어는 청중이 정한다.** 코드가 최근 대화의 `[Chat]` 줄(플레이어만, 자기 발언 제외)에서
  발화자별 한글·라틴 비율을 세어 `Language:` 한 줄을 프롬프트 절에 넣는다. 발화자 전원이
  한국어면 계속 한국어, 전원 영어면 계속 영어. 섞였거나 아무도 말하지 않아 모르면 한국어 →
  영어 → 한국어로 주제마다 번갈아 한다. 주인공 이름의 문자는 보지 않는다.
- `bard.txt`의 Tales 절이 위 순서와 JSON 예시를 담는다. 덧붙여:
  - **주어진 사실에 없는 사건·인물을 넣지 않는다.** 색칠은 좋고 창작은 안 된다. 실패는
    비극으로 부르지 조롱하지 않는다.
  - 빈 자리에서는 부르지 않는다(이미 "듣는 사람이 없으면 LLM 호출 낭비" 게이트가 있다).
  - 주인공이 자리에 있으면 한 줄 인사를 덧붙인다 — "오늘의 주인공이 여기 계시네요".
    world state의 근처 플레이어 이름과 주제의 이름을 대조하면 된다. 이 한 줄이 실명
    콘텐츠의 보상이다.
  - 청중이 "그거 진짜야?"라고 물으면 "노래는 노래죠"로 받는다. 바드는 기자가 아니다.
- **저녁 여관 공연에서만 부른다.** Signe의 일과(`npcs/signe/schedule.json`)는 낮엔 광장
  버스킹, 19:00부터 여관 공연이다. 원장 절은 여관 공연 일정이 활성일 때만 프롬프트에
  넣는다 — 낮 광장에서는 파일을 읽지 않으니 프롬프트 규칙이 아니라 코드 게이트다.
  일정 항목에 `tales: true` 같은 플래그를 두고 그 항목이 활성일 때만 읽으면 일정을 옮겨도
  코드가 안 바뀐다. 광장은 지나가는 사람 상대의 짧은 곡, 여관은 자리 잡고 앉은 사람
  상대의 긴 이야기라는 구분이 자연스럽고, 밤에 여관에 갈 이유가 하나 생긴다.
- 낭송 범위는 채팅 범위(`EVENT_DELIVERY_RADIUS`)다. 여관 밖 사람은 못 듣는다. 의도다.

## 성능

서버는 `/recite` 한 줄뿐(발화와 같은 fan-out). 감사 때 원장 append + NPC 턴당 작은 파일 읽기 하나. 가사는 9초에 한 메시지라 채팅보다 적다. 5,000명 규모와 무관하다.

## 후보 — 하지 않기로 한 것과 미룬 것

- **서버 자동 수집** — 서버가 사건을 원장에 직접 쓴다. "무엇이 노래감인가"(창 안 최고인지,
  서버 최초인지)의 판단이 아직 사람 손에 있어 미룬다. 카탈로그가 굳으면 자동화 후보.
- **다른 NPC의 언급** — Rica의 소문, Karl의 "그 녀석 봤지". 원장을 `tales/`에 둔 이유.
  Signe로 한 달 굴려 보고 결정.
- **여관 밖 전달** — 로그인 공지, 게시판, 낮 광장 공연. 밤에 여관에 가야 듣는 지금 구조가 먼저.
- **주인공 보상** — 노래에 오른 사람에게 칭호("노래에 오른 자"). 칭호 `source`에
  `tale` 경로 추가로 가능하지만, 사람이 고른 결과에 서버 보상을 붙이는 건 공정성 문제라
  보류.
- **플레이어 투고** — "내 이야기 불러줘". Signe 메모리로 이미 반쯤 된다. 원장과 섞이면
  "원장에 없는 사건은 안 부른다"가 무너지므로, 넣더라도 별도 파일로.
