# 레벨 곡선 재설계

레벨업에 필요한 경험치 표를 **플레이 시간**으로부터 역산해 다시 정한다. 현재 곡선은
`XP(n) = 20 × 2^(n−2)`(COMBAT.md)로, 레벨마다 두 배라 초반은 순식간이고 20 이후는
사실상 도달 불가다. 목표는 표준 유저가 50레벨에 약 50일 만에 닿는 완만한 곡선이고,
50 이후만 지금처럼 두 배 곡선을 남긴다.

REPEAT_FARMING.md의 결론대로 곡선은 파밍 제동 장치가 아니다. 이 표는 **페이스**만 정한다.

## 목표 페이스

표준 유저: 하루 4시간 플레이.

| 요구 | 곡선 |
|---|---|
| 초반은 1~2시간 안에 레벨업 | 2~10레벨: 레벨당 5분 → 22분 (10레벨 누적 2시간) |
| 평균 하루 한 번 | 10~30레벨: 22분 → 5.5시간 |
| 후반은 이틀에 한 번(7~8시간) | 30~50레벨: 5.5 → 8시간 |
| 50레벨까지 약 50일 | 합계 199시간 = **50일** |
| 50 이후 필요 경험치 두 배 | `XP(n) = XP(50) × 2^(n−50)` (n > 50), u64 포화 |

레벨당 시간은 위 세 구간을 잇는 꺾은선이다. 꼭짓점 네 개
`(2, 5분) (10, 22분) (30, 5.5h) (50, 8h)`가 조정 손잡이다. 문자 그대로 "하루 한 번"은
25레벨 부근에서, "7~8시간"은 42레벨 이후에 성립한다.

## 가정

- **시간당 처치 수 K = 100.** 유일한 보정 상수. REPEAT_FARMING 2부(레벨 차 감쇠·위험
  보너스)가 들어가면 다시 잰다.
- **실측(2026-08-20 ~ 08-26, prod 처치 로그 336,618건, 활동 2시간 이상 40명).** 킬 간격
  10분 이내를 활동 시간으로 잡으면 시간당 처치는 중앙값 172, 시간 가중 275로 K의 2~3배다.
  그러나 실제 사냥감은 자기 레벨보다 한참 아래다(13~20레벨 유저의 사냥감 중앙값 5~13).
  둘이 상쇄되어 **시간당 XP는 모델의 0.4~1.2배, 중앙값 0.85배**로 K=100·사냥감=자기
  레벨 모델과 맞는다. 로스터 상한(15) 때문에 16레벨 이상은 이미 표보다 느리다.
- **사냥감 레벨 = 플레이어 레벨.** 레벨 L 유저는 레벨 L 몬스터를 잡는다고 본다. 로스터의
  guard가 `레벨 + 7`이라 `monster_xp = L² + 2L − 5`(1~3레벨은 코볼드 2, 고블린 5,
  스토커 10). 오늘 로스터에 이걸 맞추면 로스터를 늘릴 때 표를 또 바꿔야 하므로 표는
  콘텐츠 쪽을 기준으로 둔다.
- 파티 보너스, 위험 보너스는 세지 않는다. 모두 K를 올리는 방향이므로 실제 페이스는 표보다
  빠르면 빨랐지 느리지 않다.

구간 XP = K × monster_xp(L−1) × hours(L), 유효숫자 두 자리로 반올림 후 누적.
생성 스크립트: `scripts/level_curve.py`.

## 콘텐츠 의존성

야외 로스터는 사이클롭스(15, 246 XP)에서 끝나고 던전 깊이 보정도 20에서 멈춘다
(`monster_level_for_depth`). 그래서 실측 페이스는 16~20레벨까지만 표대로 나오고, 그 위는
246 XP짜리를 잡아 오르는 셈이라 표보다 훨씬 느리다 — 49→50이 2,000,000 / 24,600 ≈
81시간. 의도한 성질이다: 사실상의 캡이 콘텐츠를 따라간다. 고레벨 몬스터를 추가하면 표는
그대로 두고 페이스만 살아난다.

## 마이그레이션

`characters.level`은 별도 컬럼이고 경험치를 얻을 때만 오르며 사망 페널티로만 내려간다
(`combat.rs`). 레벨은 그대로 두고 **구간 안의 진행률**을 옮긴다.

```
frac   = clamp((old_xp − OLD(L)) / (OLD(L+1) − OLD(L)), 0, 1 − ε)
new_xp = NEW(L) + floor(frac × (NEW(L+1) − NEW(L)))
```

- 게이지 퍼센트는 모든 유저가 그대로다. 숫자만 바뀐다.
- `old_xp < OLD(L)`(옛 데이터 불일치)는 frac 0. 50 초과 유저는 없으나 같은 식이 그대로
  적용된다.
- 서버 기동 시 한 번, 트랜잭션 안에서, `migrations` 테이블의 이름 플래그로 재실행을 막는다.
- 실행 전 prod DB 백업 → 로컬 scp → md5 확인.
- 사망 페널티(구간 15%, 30% 복구선)와 파티 분배는 구간 상대값이라 손대지 않는다.
